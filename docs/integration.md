# Request-bound host integration

Standalone `fenric` commands and `fenric.run` remain ordinary query/response tools. They need no authority broker. Their validated results do not by themselves prove operator origin or resolve a native harness permission request.

`fenric.run_integrated(channel, backend=None, cancel=None)` consumes one connected, host-admitted Unix stream socket. The requesting host owns the original question/action, private endpoint bootstrap, current operator policy and native callback. The questioning worker invokes Fenric; an optional coordinator may relay a protected operator URL or answer under separate delegated authority. A coordinator is never a gate for a direct operator answer. A caller-created socket, command flag, copied message, model signature or prose claim does not acquire an existing host's native approval authority.

The separate `interact` CLI entry point accepts only an inherited `--channel-fd`. It reads one request and returns all answers/status metadata through that endpoint, with no ordinary stdout result, fallback file or remote status file. Exit status describes collection: 0 answered, 2 cancelled, 3 failed and 4 expired/superseded/unavailable. It does not certify native delivery or action execution. The one-shot connection is shut down at return. The caller closes its original descriptor; Fenric closes its duplicate and makes it non-inheritable. Sink children receive no private channel.

The library's `backend` override is a trusted host integration and testing seam. The host must retain control of renderer selection and endpoint bootstrap, and keep the endpoint out of ordinary worker/model access. A scripted backend can synthesize input under the local process account; measuring that account does not prove physical operator interaction. The CLI offers no backend selection. Production qualification must establish actual renderer custody as well as native callback custody; neither a socket nor an observed UID establishes those properties alone.

## Qualification boundary

As of 2026-10-17, this packaged interface implements bounded wire parsing, request-bound rendering and synthetic/disposable integration tests. Separately, operator-reported qualification on 2026-10-16 records authenticated phone Allow once, Deny and phone Cancel in bounded standard daemon-managed Claude Write fixtures on two macOS hosts through scratch-local PermissionRequest hooks. This archive’s synthetic tests do not reproduce those operational observations. Those hooks use still-live invocation/session/input/nonce binding, not an invented tool-use ID or proof that this integrated mapping is universally installed. Existing-worker deployment, generalized native custody/restart and protected relay adoption require their own qualification; live Codex phone approval remains unvalidated. See the [worked native walkthrough](native-approvals.md). Native GUI and already configured authorized remote prerequisites remain. Headless mode refuses before remote startup; renderer failure ends the session. Native Linux/Windows GUI behavior remains unverified; this private channel currently requires POSIX UID observations and a Unix stream socket.

### Native MCP confirmation subset

The distinct `fenric.codex-mcp-confirmation.v1` mapping uses the existing `codex.question` route and `item/tool/requestUserInput` method, with original exactly `{rpc,action}`. Ordinary `{questions,rpc}` questions keep their existing mapping and behavior. The MCP branch accepts the pinned 0.163 unversioned RPC, optional valid `jsonrpc` and absent/null/closed `trace`; the older ordinary-question mapping still requires its version marker. It retains optional presence without inserting defaults. Params require matching thread/turn/item IDs, `isBlocking:true`, one question and absent/null `autoResolutionMs` only. The full action must be an in-progress `mcpToolCall` with the same item ID, exact server/tool/arguments and known typed optional metadata. Pending result/error/duration must be absent/null. Metadata URIs remain inert; no resource is loaded.

The question ID must be `mcp_tool_call_approval_` plus that action ID, header `Approve app tool call?`, and explicit false secret/Other flags. Exact native options are Allow / Cancel, optionally with Allow for this session between them, including their pinned descriptions. Only keyed Allow or Cancel can be selected or returned; the complete session alternative remains original-only information. Persistent-choice requests, including Allow and don't ask me again, refuse entirely in this bounded mapping, as do unknown, duplicate, reordered or malformed alternatives. The native question prose can be overridden by metadata; Fenric instead derives the readable action from server, tool and canonical arguments. It grants no future permission and changes no input.

The existing open Complete original request pane displays the escaped complete original and binding context. This is distinct from command-only collapsed technical details and human-readable expiry presentation. Arguments can be null or nested supported JSON, but floats, unsafe integers and the existing frame/depth/node/spec limits refuse without stringification, pruning or truncation. The native host must independently retain the full original native item and RPC, join the live item/thread/turn/request and transport generation, admit the actual response principal, and construct the vendor's keyed one-action reply for the original callback. A renderer answer alone neither invokes the tool nor proves native delivery. Automated source fixtures are not installation, production admission or live phone qualification.

## Exact wire

The shipped [closed schema](../fenric/_protocol/interaction.schema.json) defines Request, Availability, Invalidate, Response, WorkerReceipt, DeliveryDisposition and Terminal messages for `fenric.operator-response.v1`. All structural fields are required, including explicit nulls. Unknown structural members refuse. Data-bearing original/spec/answer objects have separate semantic checks.

Each frame is a four-byte unsigned big-endian byte length followed by UTF-8 JSON. The body is nonempty and at most one mebibyte. Initial request receipt has a five-second bound; subsequent frame transfers have a two-second bound. EOF, truncated/blocked frames, malformed Unicode, duplicate keys, float/exponent/non-finite numeric syntax, unsafe integers and unsupported JSON values refuse. Nesting is limited to 64 and parsed nodes to 100000. Integers use the signed JavaScript-safe range. Canonical encoding sorts Unicode scalar keys, preserves strings without normalization, uses standard JSON short escapes/lowercase control escapes and has no whitespace. The shared vectors independently bind canonical bytes, SHA-256 digests and frame bytes.

DecisionContext retains the complete original question/action, scope, native IDs, response schema, exact deterministic presentation, intended worker/session/host, principal admission and immutable expiry. Its decision digest excludes renderer transport and bearer capabilities. TransportBinding separately binds adapter instance, host generation, renderer instance and channel. Every reply retains exact correlation and settlement identities. A restarted or replaced host uses new custody; this renderer never reconnects or replays an old decision.

Positive authority lifetime is at most one hour. Admission requires the original issue/expiry interval to include the current time. A monotonic deadline derived from remaining lifetime and the original wall-clock expiry both remain enforced. The integrated ring uses remaining host lifetime; standalone spec timeouts keep their existing behavior. Touch may dismiss the visual countdown but cannot extend authority. Unsupported response-schema keywords or references refuse; the supported bounded subset covers objects/properties/required/additionalProperties, arrays/items/length/uniqueness, strings/length, integer bounds, enum/const, booleans/null and oneOf/anyOf. Dynamic additional-property schemas validate each value. Booleans never coerce to integers or numeric enum values.

## Actual surface observations

Local subject is decimal `str(os.getuid())`, authentication basis is `local_process_uid`, and node is `socket.gethostname()`. Remote subject is the exact verified Tailscale proxy login, basis is `tailscale_user_login`, and node is also the actual receiving hostname. The Serve DNS authority is transport metadata rather than a substitute node identity. Session observation is null initially because this renderer has no separately qualified session measurement. Null matches only null; it is never a wildcard or an echoed worker session.

The renderer constructs observations outside browser JSON and compares the complete tuple exactly against the digest-bound admission set, allowed surface, policy reference and issue/expiry interval before reservation. Every supplied observation retains those checks even when collection ends with an error or another non-answer status. The requesting host independently rechecks its current configured principal map when consuming the response. A proxy login is account evidence, not proof of a particular phone or physical person. Same-user local processes and the trusted local proxy boundary remain within the existing trust model.

A disallowed native surface is review-only: it cannot submit, cancel or expire eligible remote input, and closing it closes only that view. Actual host invalidation remains a different event. Immutable expiry and renderer failure still terminate the interaction. Invalid payloads do not reserve eligible input; a valid winning reservation accepts at most one answer/effect. Later invalidation never rewrites a winning answer as cancellation. It can refuse later native delivery; it cannot undo a performed write.

When the local view is review-only and the remote surface reports terminal unavailability, collection ends promptly as `unavailable` with no answer. A refused native payload receives a fixed value-free rejection marker and may be corrected; a view losing to another surface's pending sink waits for its terminal state instead of being told to retry. Valid settled remote retries and losing remote pages receive the recorded custody state without another sink, and terminal browser synchronization clears their typed inputs.

## Secret effects and delivery

Secret entry remains masked and direct to a supported file or store command. Trusted chrome shows the complete original request, receiving context and exact independently prepared destination, with a separate unchecked confirmation. The integrated secret payload's fixed top-level `destination_confirmed` atom must be true; it is checked and removed before ordinary secret-value validation. Standalone payloads remain unchanged.

File destinations compare actual resolved path, receiving host, normalized validated field names and wire format (`dotenv`, `flat-json`, `single-value`). Relative and symlink input paths are resolved rather than compared literally to the destination. Format/path identity is checked again before writing. Store destinations compare current working directory, the exact absolute invocation path from command preparation, and exact per-field argv including argv[0]. Symlink invocation semantics are preserved; labels remain caller descriptions rather than destination authority. The integration currently bounds a secret request to 32 fields.

Values never enter response frames, return metadata, native conversation, ordinary stdout/stderr, HTTP acknowledgements, model/chat/bus or logs. `filled` lists only proved completed field writes; `skipped` lists blank fields. Completed effects account for every original field. Under unknown/partial effects, unproved or unattempted fields are not relabeled written. A command can write and then exit nonzero, so failure or timeout may leave an unknown effect. No possibly completed effect is retried automatically. An effect remains recorded even if delivery or response serialization fails; `IntegratedResult.effect` preserves that status independently of the response field. Later cancellation makes no rollback promise. Stronger cross-process transactions and revocation guarantees are deferred.

This renderer emits `not_applicable`, `not_started`, `completed` and conservative `unknown` effects. The shared wire's `failed` outcome and `write-failed` detail are not emitted here: an ambiguous file/store exception is not proof that no write happened. Explicit destination admission failures remain `not_started`/`validation-refused`.

Collection, effect, authenticated worker-adapter receipt, native delivery and action completion are distinct. `WorkerReceipt.received` is the admitted host's acknowledgement, not proof that a model consumed the result. `DeliveryDisposition.delivered` is the host's correlated native-resolution/callback-return report; Fenric does not independently prove the native action executed. Missing/ambiguous acknowledgement stays unknown. `host.secret` is status-only and never submits a native approval; its native disposition remains refused/not-submitted. Terminal closed reports teardown, not consent or successful action execution.

Receipt and native-disposition admission closes before Terminal is emitted. Frames arriving after that boundary are ignored; an unacknowledged result remains unknown rather than being promoted by a late host report.

## Protected optional remote availability

Integrated mode suppresses ordinary URL stderr, status files and configured announcement subprocesses. Availability and any bearer capability travel only over the already admitted private host channel. The library return has no capability field. It does not implement a coordinator endpoint or forward capabilities into ordinary bus/model/log content. A host must qualify an already authorized protected operator sink before relaying the URL; that optional relay is currently unavailable without such proof. Local answering is independent of coordinator reachability. This feature grants no networking setup, new service, installation or permission changes.

## Selected static reports

Use an `html` spec for an unchanged caller-selected static report with an explicit `root`, HTML `entry` and `files` allowlist. Include only presentation documents/assets the user is meant to see, preserving their relative paths; do not recursively expose a build directory. Keep the original invocation and deadline, deliver its protected URL promptly through the operator-authorized channel, and collect that invocation's terminal result. Embedded report controls cannot settle the outer dialog or approve an operation. OK means presentation acknowledged, not evidence that every linked page was reviewed. Unselected links fail closed; the caller must resolve necessary omitted presentation files explicitly. In-frame activity never extends the review lifetime. Existing private lifecycle and cleanup ownership apply; no new route, hook or grant is implied.
